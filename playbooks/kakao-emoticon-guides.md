## 이번에 적용하는 내부 결정

생성형 AI를 사용했다는 이유만으로 제출 후보를 일괄 배제하지 않는다.
이슈 #10의 이전 제한 제안과 같은 취지의 운영 메모는 현재 정책으로 재사용하지 않는다.
이는 제우스의 명시적 내부 정책 변경이며 공식 가이드가 모든 제작 방식을 허용한다는 주장은 아니다.

제작 방식·도구·모델·입력 출처와 산출물 버전·해시는 계속 기록한다.
기존 결과의 품질 반려나 원형 불일치는 해당 결과의 검수 이력이다.
일괄 제한 철회로 그 결과를 자동 PASS로 바꾸거나 검수 없이 제출하지 않는다.

## 작업 순서

1. 헤스티아가 대상 플랫폼, 이모티콘 유형, 제안용/상품화용 단계, 결과 범위를 확정한다.
2. 아르테미스의 기존 규격 조사 담당자가 관련 공식 원문을 읽는다.
   URL·확인 시각·원문 변경일(제공되는 경우)·유형·단계·수치·근거 위치를 비공개 규격표에 기록한다.
   인덱스만 읽었거나 세부 원문을 읽지 못하면 해당 요구사항을 미확인으로 남긴다.
3. 제작 담당자는 작업에 고정된 원형·입력과 규격표를 사용한다. 도구 선택은 현재 권한과 예산을 따른다.
   외부 가이드 링크가 도구 설치·로그인·비용·업로드의 새 승인으로 기능하지 않는다.
4. 헤라는 이미지 규격, 원형 일치, 출처·권리, 표현 품질, 작가·시리즈 정보와 최종 패키지를 검수한다.
   정지 이미지는 실제 파일, 움직이는 이미지는 전체 재생·반복 경계·썸네일·배경별 가독성을 확인한다.
   실패 항목과 실제 근거에 해당하는 단계만 수정한다.
5. 헤르메스는 기존 제출 승인 절차에 따라 정확한 파일·정보·대상에 대한 승인 후 제출 결과를 기록한다.
   가이드 준수 검수와 카카오의 심사·승인 결과는 별도다.

## 과거 지침의 전환

실행 환경은 새 policy_commit과 이 결정 기록을 읽고, 같은 범위의 이전 일괄 제한 메모가
활성 규칙으로 주입되지 않도록 철회·대체 상태를 기록한다. 과거 결정·비용·실패 이력은 보존한다.
생성형 사용 여부만으로 막힌 업무는 다른 차단 사유를 함께 대조한 후 해당 사유만 해소한다.
원형 미승인·품질 반려·예산 부족·제출 승인 미확인까지 함께 해제하지 않는다.

헌법·프롬프트·YAML의 변경은 실제 Grokbot 메모리·Skill·Bot 적용 완료의 증거가 아니다.
실제 운영자는 로드한 커밋, 변경한 활성 지침, 재조회 결과를 같은 업무 ID에 기록한다.
