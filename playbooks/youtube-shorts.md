# 민음사 문학 YouTube Shorts 플레이북

버전: shorts-v1 · 갱신일: 2026-09-24 · 상위 규칙: [SHORTS_Operating_v1.md](../SHORTS_Operating_v1.md)

이 문서는 한 회차를 배정부터 공개까지 처리하는 순서다. 규칙이 상위 문서와 다르면 상위 문서를 따른다. 이 개정은 Studio 업로드·예약·슬롯 설정을 바꾸지 않는다.

## 1. 범위

대상은 민음사 세계문학전집 YouTube Shorts다. Fatal Giggle 신규 제작은 열지 않는다. 중단 기록은 [2026-09-06 결정](../docs/decisions/2026-09-06-fatal-giggle-production-stop.md)이다. 기존 영상·이력은 지우지 않는다. 재개는 [숏츠] 총괄의 승인요청과 사용자 명시 지시가 있을 때만 연다.

## 2. 역할

| 표시명 | 이 플레이북에서 하는 일 |
|---|---|
| [숏츠] 총괄 | 접수, 한 직무를 한 슬롯에 배분, 핸드오프 4줄, Facts / 진행 / 막힘 / 승인요청 |
| [숏츠] 배정 | 작품·권·회차 번호 확정 |
| [숏츠] 리서치 | 작품 조사만 |
| [숏츠] 대본 | 45–60초 대본 |
| [숏츠] 영상생성 | Imagine 컷 |
| [숏츠] 편집조립 | 최종 조립 |
| [숏츠] 훅·썸네일 | 훅·썸네일. 편집조립과 병행 가능 |
| [숏츠] 품질게이트 | PASS / CONDITIONAL / FAIL |
| [숏츠] 채널기준 | 채널 적합성 피드백. 판정을 바꾸지 않음 |
| [숏츠] 발행게이트 | 발행 준비 확인. 업로드하지 않음 |
| [숏츠] 메타·공개 | 메타데이터와 업로드·공개만 |
| [숏츠] 채널운영 | 슬롯·큐·홀드 상태. 없으면 총괄이 기록 |

## 3. 파이프라인

배정 → 리서치 → 대본 → 영상생성 → 편집조립 → (훅·썸네일 병행) → 품질게이트 → 발행게이트 → 메타·공개

품질게이트 전에는 최종 영상과 훅·썸네일이 모두 있어야 한다.

## 4. 핸드오프와 보고

총괄의 지시는 네 줄이다.

```
역할: [숏츠] 리서치
산출: 회차 번호의 작품 사실·출처·인용 범위
성공: 대본에 필요한 사실이 출처와 함께 적힘
금지: 대본 작성, 컷 생성, 업로드
```

슬롯의 보고는 네 항목이다.

```
Facts:
진행:
막힘:
승인요청:
```

## 5. 단계별 완료

1. **배정.** 회차 번호 하나. 큐 선두와 #100 이후 순서를 건너뛰는 번호를 확정하지 않는다. UPLOAD-HOLD 해제 후 첫 공개 후보는 #100이다.
2. **리서치.** 작품 사실, 출처, 인용 범위. 대본을 쓰지 않는다.
3. **대본.** 낭독 45–60초. 조사 범위 안에서 장면 순서를 적는다.
4. **영상생성.** Imagine으로 대본 컷을 만든다. 폭력, 혈흔, 손 이상이 보이면 그 컷을 넘기지 않는다.
5. **편집조립.** 컷을 한 편으로 조립한다. 컷 번호·내부 라벨·작업 메모가 화면에 남으면 조립 완료로 보지 않는다.
6. **훅·썸네일.** 편집조립과 병행할 수 있다. 초반에 상황과 볼 이유를 말하고, 썸네일은 영상과 같은 내용을 약속한다.
7. **채널기준.** 문학 숏츠에 맞는지 피드백한다. 카드광고, 양산 유머, 쇼핑·제휴, 채널 구매, 조회수 판매, CapCut 교체를 대안으로 제안하지 않는다.
8. **품질게이트.** PASS, CONDITIONAL, FAIL 중 하나와 근거. 길이만으로 PASS하지 않는다.
9. **발행게이트.** 품질 PASS, 파일, 메타 초안, 선두 순서, UPLOAD-HOLD 아님, Studio 한도 아님.
10. **메타·공개.** 제목·설명·태그·썸네일을 최종 영상과 맞춘 뒤, 발행게이트가 허용하고 홀드가 없을 때만 업로드·공개한다. 원격 결과를 Facts에 남긴다.

## 6. 큐와 슬롯

공개 슬롯은 **07·12·15·18·19·21 KST**다. 실제 채널 시각은 Studio에서 확인한다. 이 문서로 스케줄을 켜지 않는다.

| 상태 | 처리 |
|---|---|
| 품질게이트 PASS | 대기 큐 끝에 추가. 업로드는 아님 |
| CONDITIONAL, FAIL, 미검수 | 홀드. 총괄이 PASS로 바꾸지 않음 |
| 홀드 항목이 다시 PASS | 원래 순서로 복귀 |
| 선두가 대기 중 | 뒤 번호를 먼저 공개하지 않음 |
| UPLOAD-HOLD 또는 Studio 한도 | 업로드하지 않음. 재개 지시 뒤에만 업로드 |
| 이미 공개된 번호 | 같은 채널에 다시 올리지 않음 |
| 버퍼가 목표보다 적음 | 새 공개보다 앞 회차 제작을 우선. 목표 편수 N은 총괄 승인요청으로 정함 |
| 큐를 PASS로 채울 수 없음 | 공백을 기록. 다른 소재로 대체하지 않음 |

[숏츠] 채널운영이 있으면 슬롯·큐·홀드를 기록한다. 없으면 [숏츠] 총괄이 기록한다. 둘 다 업로드하지 않는다.

## 7. 게이트 체크리스트

품질게이트는 회차마다 아래를 표시한다.

- 낭독 45–60초
- 훅이 초반에 상황과 볼 이유를 전달함
- 제목·썸네일·영상이 같은 약속
- 장면 순서가 대본과 연결됨
- 음성·자막·음량이 이해를 막지 않음
- 화면에 컷 라벨·내부 번호·작업 메모가 없음
- 혈흔·유혈이 없음
- 손이 이상하지 않음
- 폭력 연출이 없음
- Fatal Giggle 요소가 없음
- 기여 한 줄이 있음

컷 라벨이나 혈흔으로 FAIL이면 같은 항목을 고친 뒤 다시 품질게이트로 온다. 체크를 지우고 넘기지 않는다.

## 8. 같은 회차 재시도

1. 실패 슬롯은 입력·산출·원인을 총괄에 보고한다.
2. 같은 회차의 다시 하기는 총괄이 연 핸드오프만 수행한다.
3. 새 핸드오프에 이전 산출, 원인, 바꿀 점을 적는다.
4. 훅 실패 원인이 대본일 때만 대본 핸드오프를 연다.
5. 같은 실패가 두 번이면 자동 반복을 멈추고 승인요청에 올린다.

## 9. 주간 개선

Studio에서 확인한 조회와 이탈만 사용한다. 확인하지 못한 수치는 미확인이다.

1. 첫 장면에서 무엇을 약속하고 어디에서 나가는가?
2. 대본·장면·편집 중 이해가 끊기는 구간이 있는가?
3. 음성·자막·화면이 거부를 만드는가?
4. 제목·썸네일과 영상이 다른가?

확인된 이탈은 [숏츠] 훅·썸네일와 [숏츠] 대본의 다음 회차 핸드오프에 적는다. 좌우반전, RGB 변경, VPN, 기계적 댓글·좋아요, 민감어 치환을 처방으로 쓰지 않는다.

## 10. 언어와 표현

핸드오프, 보고, 대사, 자막, 제목, 설명은 한국어만 쓴다. 신화 연기와 난로 비유를 쓰지 않는다. 역할 이름은 이 문서의 표시명만 쓴다.
