# 이모티콘 상품 제작

기준: [헌법 v1.4](../OLYMPUS_Agent_Architecture_v1.4.md) `OLY-EMO-001..002`, `OLY-CHR-001`, `OLY-ROLE-001`
단계: DOCUMENTED / 실제 상품 제작·Bot 변경·제출 실행: 미검증

## 1. 상품과 원형을 분리한다

상품마다 고유한 `project_id`, `product_id`를 만든다. 공통 캐릭터는 별도 `character_id`와 승인 원형의 ID·버전·SHA-256으로 연결한다. 이름이 비슷하다는 이유로 원형·검수·상품 단계를 합치지 않는다.

| 트랙 | 현재 문서상 의미 | 함께 승격하지 않는 것 |
|---|---|---|
| 밤 `BAM` | 공통 캐릭터 원형 후보와 변형 자료 | 상품 시안 통과가 밤의 원형 승인이 되지 않음 |
| 밤티나는 밤이 S1 | 별도 이모티콘 상품 프로젝트 | 밤 원형의 파생 READY 또는 제출본으로 자동 분류하지 않음 |
| 직업도밤 C3 파일럿 | 지정 범위의 파일럿·규격화 작업 | 전체 세트 제작·제출 권한으로 확대하지 않음 |

위 상태는 저장소 및 이슈 기록에 근거한 분리 기준이다. 실제 최신 파일·승인·Bot 연결은 운영 환경에서 확인한다. 특정 인간의 이름이나 파일럿 수량·문구 수는 헌법 상수로 고정하지 않고 상품 카드에 기록한다.

## 2. 단계별 산출물과 게이트

| 단계 | 책임 | 입력·산출물 | 다음 단계 조건 |
|---|---|---|---|
| 상품 정의 | 아테나 | 대상·사용 상황·상품 범위 | 상품·플랫폼·제안/상품화 단계 명시 |
| 규격 조사 | 아르테미스 | 공식 출처·확인 시각·유형별 규격표 | 필요한 원문을 실제 확인; 미확인 수치를 추정하지 않음 |
| 외형·명세 | 아프로디테 | 기존 원형 참조·유지 특징·허용 변형 | 헤라 명세 검수 PASS; 기존 외형 재설계는 제우스 승인 |
| 매트릭스 | 아프로디테·아폴론의 별도 카드 | 표정·포즈와 문구 목록 | 헤라 중복·상황·가독성 검수 PASS |
| 원화·동작 | 아프로디테 | 지정 제작 주체의 개별 시안·원화·동작 | 카드의 제작 방식·원형·참조·권한·예산 확인 |
| 개별 검수 | 헤라 | 정확한 파일 버전·해시의 검수 | 모든 필수 조건 PASS; CONDITIONAL_PASS는 수정 대기 |
| 규격화 | 헤파이스토스 | 검수 파일의 포맷·크기·파일명·패키지 | 외형 재작도 없이 규격 검사 |
| 최종 검수 | 헤라 | 최종 파일·작가/시리즈 정보·출처·권리 | 대상 단계의 최신 규격과 원형·품질 PASS |
| 제출 | 헤르메스 | 전체 제출 매니페스트·제우스 승인 | 승인·제품 요구사항 확인 후 원격 접수 결과 기록 |

명세·매트릭스 통과 전에 원화를 먼저 대량 생성하지 않는다. 신규 원형 탐색은 기존 `APHRODITE-CHARACTER-DESIGNER`와 [시안 실행 템플릿](../templates/emoticon-draft.yaml)을 사용한다. 승인 원형의 개별 파생 그림은 `APHRODITE-CHARACTER-ILLUSTRATOR`를 사용한다. 신규 원형을 탐색하는 시안은 `DRAFT_CANDIDATE`로만 생성하고 후보 입력·제작 방식의 명시 허용 범위를 기록한다. 이는 승인 원형의 파생 자산이 아니므로 CHARACTER 파생 제작의 READY 조건을 우회하지 않는다. 제출·공통 자산 재사용으로 넘어가려면 원형 승인과 정확한 최종 자산 검수가 필요하다.

## 3. 카드에서 분리할 값

[상품 카드 예시](../templates/emoticon-project.yaml)를 사용한다.

- `artwork_source`: USER / EXTERNAL / REGISTERED_HUMAN과 실제 주체의 비공개 참조. 기존 인간을 먼저 확인하고 이름만으로 새 봇을 만들지 않는다.
- `generative_ok`, `generative_scope`: 해당 상품·단계의 생성형 제작 허용. 미결정은 `null`로 기록하고 필요한 제작 방식 결정만 확인한다. 일괄 금지로 해석하지 않는다.
- `submit_requires_zeus`: 제출 클릭·업로드는 제우스 승인 대상이다. 시안 허용과 독립적으로 유지한다.
- `canon_ref`, `spec_ref`, `matrix_ref`, `review_ref`: 정확한 버전·해시·검수 참조. 빈 값을 승인 완료로 취급하지 않는다.
- `target_stage`, `production_stage`: 플랫폼의 제안/상품화 단계와 내부 시안/제작/패키지 단계를 따로 기록한다.

이슈 #9의 2026-09-08 정정에 따라 밤티 S1의 생성형 **시안** 허용을 기록한다. 직전 댓글의 AI 금지 메모는 같은 범위에서 대체되었다. 헤파이스토스 원화 배분 금지, 원형·품질 검수, 제출 승인은 유지한다. 이 기록은 기존 결과의 CONDITIONAL_PASS를 PASS로 바꾸지 않으며 다른 상품에 자동 확장하지 않는다.

## 4. 파일 변환과 제출

기존 얼굴·선·잎·체형을 다시 그리는 작업은 규격화가 아니다. 배경 제거·외곽선 복원 등 시각 편집도 아프로디테의 별도 카드와 검수를 거친다. 헤파이스토스는 승인된 입력의 크기·형식·파일명 변환과 패키징을 수행한다.

카카오 규격은 [공식 가이드 적용 절차](kakao-emoticon-guides.md)로 제작·제출 전에 확인한다. 다른 플랫폼은 각 공식 근거를 따로 확인한다. 이번 개정은 플랫폼의 AI 허용·금지·심사 통과를 판정하지 않는다.

최종 파일이 바뀌면 해당 파일과 후속 패키지의 검수·제출 매니페스트를 갱신한다. 재작업 횟수·비용은 같은 계보로 누적한다. 제출 응답이 불명확하면 원격 접수 내역 대조 전 재제출하지 않는다. 제품상 사용자 조작이 필요하면 `OLY-HND-001`로 인계한다.
