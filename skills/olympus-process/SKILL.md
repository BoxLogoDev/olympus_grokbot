# OLYMPUS 공통 Process

헌법 v1.3, OLY-OPS-001..006, OLY-TPL-001, OLY-RTN-001을 따른다.
정책 출처 커밋은 30363791228181b986cc94491ab938ee544699f4다.

1. 헤스티아가 요청·완료 조건·입력·상위 예산·공개 여부·필요 신을 정하고 기존 검증 절차를 선택한다.
2. 해당 신이 기존 인간을 검색해 단일 직무를 선택한다. 단일 업무 담당과 검수자를 다르게 지정한다.
3. 프로젝트 카드에 정책·Skill·모델이 노출되는 경우 모델·도구·기억·원형·입력 버전을 고정한다.
4. 실제 파일 원장 CLI로 claim 후 제작한다. 호출하지 못하면 배정을 성공한 것으로 표시하지 않는다.
5. 결과 파일·필수 점검 근거·사용량 근거를 submit한다. 비용을 모르면 null로 제출하여 대조 대기한다.
6. 부모 신의 직무 검수 후 지정된 독립 검수자가 claim(REVIEW), review를 수행한다.
7. 내부 파일 완료와 외부 실행 완료를 분리한다. 정책·승인 인증이 연결되지 않은 실행은 차단한다.
8. 예외만 원인·해결 선택지·남은 한도와 함께 헤스티아에게 반환한다. 내부 정상 인계로 사용자에게 재질문하지 않는다.
9. 헤스티아가 결과·핵심 결정·산출물·품질·승인과 실행·비용과 시간·막힌 지점·다음 수확을 보고한다.

인계 봉투: project_id, task_id, attempt_id, 입력 자산 참조, 다음 행동, done_when,
남은 예산·시도 한도, 검수 참조. 전체 대화를 반복 전달하지 않는다.

중단 결과는 block→대조→reconcile. 응답 불명은 재실행하지 않는다. 입력 변경은 change-input,
재카드는 retry로 원 작업을 참조한다. 이전 결과·실패·비용은 보존한다.

기억은 propose→verify→activate, 적용 범위·유효기간·철회 상태를 검사한다. 배포 후보는 같은 자료에서
품질 회귀 없이 비용·시간 모두 개선될 때 검토한다. 미검증 기억이나 합성 실행을 성과로 승격하지 않는다.

Grokbot의 실제 설정과 원장의 주장은 별개다. Bot ID 문자열·Notion 문서·로컬 파일만으로
인증된 제우스 승인을 발행하지 않는다. 관련 도구를 통해 확인한 값만 기록한다.

공통 입력·원형 변경은 change-reference로 전체 소비자와 후속 단계의 영향을 검토한다. handoff 출력으로 다음 담당자에게 인계한다. reuse는 유효한 후보만 찾으며 새 업무의 독립 검수를 생략하지 않는다.

GitHub·Notion·Craft 기록·인계에는 [olympus-tool-use](../olympus-tool-use/SKILL.md)를 적용한다. 기준 원본을 찾고 변경 후 실제 내용을 다시 읽어 확인한다.
