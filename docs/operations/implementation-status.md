## 조문별 적용 수준

표의 도구 강제는 이 CLI를 통과한 요청에만 적용한다. 공유 컴퓨터의 직접 파일 수정이나 다른 도구 호출을
권한으로 통제하는 서비스가 아니다. Bot ID는 운영자가 제공한 식별자이며 인증된 신원·승인으로 인정하지 않는다.

| 조문 | 문서 규칙 | 봇 지침 | 도구에서 강제 | 실제 검증 |
|---|---|---|---|---|
| OLY-OPS-001 절차 재사용 | 현행 유지 | 공통·라인 Skill 초안 | 정책 고정, DAG 검증, 버전별 단계·검수 정의 해시, 검증된 재사용 후보 | NOT_RUN |
| OLY-OPS-002 복구·부분 재실행 | 현행 유지 | block→reconcile, 원 업무 계보 | 예약·점유 보존, 늦은 결과 거부, 공통 자산 직접 소비자·후속 단계 원자적 무효화 | NOT_RUN |
| OLY-OPS-003 평가 | 현행 유지 | 제작 전 검수표·독립 검수 | 파일·SHA-256·필수 검사·현재 시도 결합, 반려 사유 필수 | NOT_RUN |
| OLY-OPS-004 기억 | 현행 유지 | 원시 피드백은 후보 | 독립 검증·쓰기 검증 근거, 프로젝트 범위·기한·철회 검사 | NOT_RUN |
| OLY-OPS-005 버전 비교 | 현행 유지 | 사전 비교 계획·회귀 시 복귀 | 같은 버전 실제 증거 2건·불변 스냅샷 검사, 합성 자료 제외, 두 지표 동시 개선 | NOT_RUN |
| OLY-OPS-006 자원 통제 | 현행 유지 | 책임 인간·총예산·검수 여유 | 전역 인간 점유, 상위 예산, 검수 대기·용량·별도 예약, 초과액 정산·중지 | NOT_RUN |

`LOCAL_TESTED`는 코드 시험 범위다. `RUNTIME_VERIFIED`는 실제 시험한 라인·정책·Skill 버전·규칙과
증거를 갖춘 운영 수용 기록에만 붙인다. 원장 출력의 `runtime_verified`는 자동으로 참이 되지 않는다.

초기 조사에서는 운영 프로필 스냅샷을 확보했지만 최근 작업 상세·실제 청구·실행 증거를 직접 대조하지 못했다.
프로필 개수나 문서 수로 성공률·비용 절감을 추정하지 않는다. 라인별 최근 최대 20건을 확보하거나 다음 실제 업무부터 측정한다.
비용 단위가 다른 자료는 합산하지 않으며 미확인 비용을 0으로 기록하지 않는다.

단위 테스트와 파일 스모크는 모두 격리된 TEST 자료다. 테스트 내부에서 REAL 플래그의 거부·수용 분기를
시험하더라도 운영 수동 검증에 포함되지 않는다.

## 전환 조건과 미구현 경계

1. 기존 헤스티아를 통해 최신 Bot·Skill·도구·루틴·예산·승인·저장 위치를 export하고 복구 가능한 원본을 보존한다.
2. 기존 인간을 현행 슬롯에 대조한다. 불일치·중복 루틴 후보를 검토하고 ID를 새로 만들거나 덮어써서 맞추지 않는다.
3. 격리 위치에 검토 커밋 설치 후 스모크를 실행하고 실제 업무용 DB를 별도로 초기화한다.
4. 각 라인 최종 Skill 버전으로 수동 종단간 통과 2건을 확보한다. 예상 밖 사용자 오류 수습은 통과로 세지 않는다.
5. 라인별 사전 고정한 20쌍을 비교한다. 품질 회귀·차단 위반이 없고 비용·완료 시간이 모두 개선돼야 제한 적용 검토 후보가 된다.
6. 신규 업무 선택·실제 Skill 적용을 각각 기록한다. 루틴 활성화는 실제 수용과 기존 승인 조건을 충족한 후 별도 수행한다.

이 릴리스는 인증된 Grokbot 실행 게이트, 외부 게시·배포·구매 실행, 자동 인벤토리 수집,
완전한 기존 YAML 요청 변환기, 공유 파일 접근자에 대한 권한 격리를 제공하지 않는다.
기존 프로젝트·업무·산출물 계약의 핵심 필드를 CLI에 고정했으며 실제 승인 인증과 도구 실행 연결은
기존 운영 환경 확인 후 구현·검증해야 한다. 외부 실행 요청은 차단된다.

캐릭터·이모티콘 제작은 승인 원형 파일·승인 근거를 준비 조건으로 요구한다.
원형을 만드는 제안·승인은 기존 캐릭터 절차에서 먼저 수행한다. 원형 승인 전 제작 완료를 꾸미지 않는다.

## 도구 활용 개선 적용

[도구 사용 Process](../../playbooks/tool-coordination.md)와 호출·인계 기록 양식을 추가했다.
Notion 운영 내보내기 요약을 추가 수신했다. 첫 조회의 JSON 본문은 비어 있었고 이후 축약본 첨부로 갱신됐다.
현재 수신 연결의 첨부 다운로드가 거부되어 전체 상세 자료의 인계 검증은 보류했다.
패키지 반입 보고는 원격 설치·실행 검증과 구분한다. 현재 Craft 호출의 연결 실패는 대체 export 경로로 처리한다.
도구별 업무 원본·업무 ID 연결·읽기 확인·수신 확인은 지침 수준이며 자동 동기화는 미설치다.
