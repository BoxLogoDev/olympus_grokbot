## 구현 경계

로컬 실행 원장은 가상 담당자와 가상 산출물 메타데이터를 사용한다. 실제 인간 레지스트리, 캐릭터 원형 승인, 모델·이미지·영상 도구, 외부 게시와 연결하지 않는다. 원장의 상태 전이·비용·복구 동작을 시험할 수 있으나 전체 올림푸스 정책을 운영 환경에서 강제한다고 주장하지 않는다.

오프라인 평가 도구는 입력 사례의 해시, 기존·후보의 동일 과제·시도·환경·평가자·정책 버전을 확인한다. 채택률·첫 검수 통과·실패 비용을 포함한 산출물당 비용·소요 시간·사용자 수정·평가자와 사람의 일치도를 보고한다. 충분하지 않은 사례나 짝이 맞지 않는 실행으로 승격을 추천하지 않으며, 합성 자료는 항상 `DEMO_ONLY`로 표시한다. 비교 결과는 승인 이벤트나 실제 성능 보증이 아니다.

기억 승격, 실사용 버전 전환, 검증된 반복 일정 활성화, 공개 승인 큐와 인증된 실사용 도구 연결은 계약을 정의한 단계다. 실제 외부 실행·예약을 활성화하지 않는다. 수동 실행 2회 규칙은 기존의 루틴 활성화 최소 조건이며 통계적 신뢰성의 증명이 아니다.

## 보존 범위

v1.0·v1.1·v1.2 헌법과 프롬프트, 이전 결정 기록, 인간 비삭제와 단일 직무 원칙, 89개 슬롯, 등록 인간의 빈 상태, 밤의 승인 대기 설정을 보존한다. 기존 이슈 #1·#2의 채택·보류와 채널 운영 기준도 유지한다. 새 신이나 인간 슬롯은 추가하지 않는다.

## 검증과 후속 적용

커밋 전 Python 3.12에서 원장 18개·평가 12개, 총 30개 단위 테스트가 통과했다. 계약 참조·기존 정책 보존·문서 링크도 정적 검증을 통과했다. 밤 데모는 가상 시도 6회·비용 18단위·예약 잔액 0으로 끝났고, 입력이 바뀐 표정과 후속 패키지만 새 세대로 처리했다. 같은 DB를 다시 열면 시도·이벤트 수가 증가하지 않았다. 평가 예시는 `DEMO_ONLY`이며 버전을 승격하지 않았다.

검토 중 발견한 지연된 이전 검수의 오적용과 동시 조회의 혼합 상태를 각각 시도 ID·결과 해시 결합, 일관된 읽기 트랜잭션으로 수정하고 회귀 테스트를 추가했다. 사람 검수와 결정적 검사를 같은 개선 기준으로 비교하는 입력도 거부한다.

테스트 통과는 해당 로컬 시나리오에 한정한다. 첫 실제 파일럿에서는 도구 바인딩과 승인 기록을 갖춘 뒤 1차 검수 통과율·전체 비용·완료 시간·사용자 수정 횟수를 수집해 이 설계의 효과를 판단한다.
