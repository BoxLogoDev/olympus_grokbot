# OLYMPUS Process 운영 패키지 0.1.0

승인된 구현 계획을 현행 헌법 v1.3의 OLY-OPS-001..006에 연결한다. 헌법의 지휘 체계,
89개 슬롯과 기존 인간 레지스트리는 변경하지 않는다. 규칙 개정이 아닌 실행 도구 추가다.

## 구현 경계

- `runtime.ledger`는 기존 시뮬레이션으로 유지한다.
- `runtime.operations`는 실제 파일·검수·사용량 증거를 기록하는 별도 SQLite 원장이다.
  파일 해시 검증, 동시 점유, 상위 예산, 검수 예약, 복구, 입력 변경을 하나의 쓰기 트랜잭션에서 처리한다.
- 실제 시스템 호출과 신원 인증은 제공하지 않는다. 운영자가 제공한 근거는 OPERATOR_SUPPLIED로 표시한다.
- 인간 ID·Bot ID 연결은 명시적으로 가져온 기존 프로필만 사용한다. 슬롯과 직무를 일치시켜야 등록할 수 있다.
- 입력·이전 시도·검수·실패·비용 이력을 보존한다. 입력 세대와 결과 해시를 묶어 늦은 결과를 거부한다.
- 검수에도 비용과 인간 점유를 예약한다. 제작 대기 상한에 도달해도 별도 검수 용량을 사용할 수 있다.
- 원시 기억은 바로 주입하지 않는다. 검증과 적용 근거·범위·유효기간이 필요하다.
- 같은 workflow_ref로 단계·검수·Skill 구성을 바꾸면 실제 프로젝트 생성을 거부한다.
  수동 검증은 입력·결과·시도 스냅샷에 묶으며 결과 수정 후 재사용할 수 없다.
- 재사용은 현재 파일·검수·입력 지문이 유효한 후보를 찾는다. 새 업무의 독립 검수를 생략하지 않는다.

## 확인한 검증

Windows / Python 3.12에서 단위 테스트 72개, 기존 계약 검사와 새 Process 계약 검사가 통과했다.
로컬 5라인 파일 스모크는 TEST로 실행했고 실제 지표 집계에서 5개 모두 제외되는 것을 확인했다.
GitHub CI는 Ubuntu·Windows의 Python 3.11·3.12 네 조합에서 같은 검사를 실행한다.
원격 CI 결과는 PR checks를 기준으로 확인한다.

현재 실제 Grokbot 설치나 10회의 수동 종단간 검증을 수행하지 않았다.
현재 상태·초기 지표·운영 대기 조건은 [운영 적용표](../operations/implementation-status.md)에 기록한다.
설치 절차는 [Grokbot 설치 안내](../../playbooks/grokbot-process-install.md)를 따른다.

## 도구 사용 Process 추가

기준 원본, 업무 ID 연결, 도구 호출 후 읽기 확인, 인계 수신 확인, 갱신·충돌·연결 장애 처리와 측정 기준을 추가했다.
관련 지침은 [도구 사용 Process](../../playbooks/tool-coordination.md)다. 공통 Skill은 0.1.1 초안으로 갱신했다.
빈 Notion JSON 블록과 필수 목록이 없는 요약을 불완전 인계로 거부하는 회귀 검사를 추가했다. 외부 DB나 웹훅은 설치하지 않았다.
