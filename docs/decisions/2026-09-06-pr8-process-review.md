## 검증

- 기존 테스트 77개 통과를 먼저 확인했다. 추가 회귀 시나리오 10개는 수정 전 모두 실패했다.
- 수정 후 전체 87개 테스트, 기존 계약 검사, Process 계약 검사 통과.
- 다섯 라인 파일 스모크: TEST 프로젝트 5개, 실제 수동 검증 0회, 외부 호출 0회.
- CI에서 Ubuntu/Windows × Python 3.11/3.12에 위 검사를 수행한다. PR의 push/pull_request 중복 실행을 줄이고, 새 커밋이 오면 같은 PR의 이전 실행을 취소한다. main의 push 검사는 유지한다.

이는 코드 회귀 검증이다. 실제 Bot 설정·실행 연결·인증 승인·제작 품질·비용·시간 개선을 검증한 것은 아니다.
헌법·슬롯·인간 레지스트리·밤 원형의 상태는 이번 검토의 변경 대상이 아니다.
새 제안 이슈 #9는 별도의 헌법·상품 정책 판단이므로 이 PR의 코드 수정으로 채택·종결하지 않는다.

## 다음 적용 순서

1. 검토 커밋을 격리 경로에 설치하고 코드 커밋·환경·검증 로그를 비공개 기록에 연결한다.
2. 기존 DB를 SQLite backup API로 보존한다. 구 절차 정의 해시·검증 행을 덮어쓰지 않는다.
3. 연결부가 새로운 next_action 값과 result_digest를 처리하는지 확인한다. 중단·반려·상위 수정 범위를 TEST 업무에서 재현한다.
4. 신규 후보는 완료 조건·검수자 설정·Skill·도구·새 workflow_ref를 고정한다. 기존 미완료 업무의 계보와 한도를 유지한다.
5. 라인별 같은 최종 버전 실제 수동 통과 2회(총 10회), 라인별 20쌍 비교와 독립 검토 후 제한 적용 여부를 판단한다.

완료 보고는 코드 반영, 설치 확인, 실제 작업 증거, 성과 비교를 각각 기록한다.
외부 게시·배포는 기존 승인 경로에서 별도로 확인하며 원장 자체의 외부 실행 차단을 유지한다.
