# 이슈 #1·#2 판단 및 v1.1 반영 기록

결정일: 2026-09-05

권한 근거: 사용자가 두 이슈의 판단, 필요한 헌법 수정, 채택 후 이슈 종료를 명시적으로 위임했다.

기준선: `68ca299a3aae6be788c5eddbafe8ab9c3a7837b3`의 v1.0. 새 문서 기준선: v1.1. v1.0 헌법·프롬프트와 인간 레지스트리의 이력은 보존한다.

## 1. 문서 반영과 실행 적용

- 이 변경의 목표는 채택 항목의 **문서·계약 반영**이다. 실제 Grokbot 설정, 인간 생성·배정, 루틴 등록, 유튜브 게시를 수행하지 않는다.
- 기본 브랜치 반영 후 각 원본 이슈 댓글에 실제 커밋 SHA와 검증 결과를 남긴다. 이 문서에 자기 자신의 커밋 SHA를 미리 기입하지 않는다.
- 실행 적용 상태는 `NOT_VERIFIED`다. 실행 환경이 `policy_version: 1.1`과 `policy_commit`을 로드하고 수용 테스트를 통과한 후에만 적용 완료로 갱신한다.
- 부분 채택한 이슈의 모든 항목에 판단을 남기고 채택 항목의 문서 반영이 확인되면 `completed`로 닫는다. 원문 미확인 항목은 아래 보류 기록으로 보존하며 자동으로 채택하지 않는다.

| 넣자 5: 영상제작 기본기 아티클 | DEFERRED | 원문과 보조 링크를 이번에도 가져오지 못함. 본문 확보 후 주장·근거·충돌을 확인해 별도 제안으로 재검. 이번 채택 범위에서 제외 |

| 넣지 말자 2: Auto Review 재서술 | NO_CHANGE | 제품별 승인 기능을 중복 헌법으로 신설하지 않음. 기존 일반 승인 계약만 정합성 보완 |

`DEFERRED`의 재검 조건은 **아티클 본문 확보**다. 조회 불가를 원문의 타당성에 대한 기각으로 해석하지 않는다. 원문 미확인을 이유로 이슈에 이미 완결된 독립 제안의 반영까지 막지 않는다.

## 5. 함께 수정한 계약 불일치

- `status`와 `probation_status`를 분리해 첫 업무 이후에도 시험 기간을 유지한다. 인간은 삭제하지 않는다.
- `READY` 전 담당자를 정하고 `ASSIGNED`에서 가용성 재확인·원자적 업무 점유를 수행한다.
- 실패 최초 시도·재시도·품질 수정의 횟수를 구분하고 카드 교체로 누적 상한을 초기화하지 않는다.
- 게시 승인 범위를 파일·메타데이터·대상·공개 설정·예약 시각 전체로 묶는다. 불명확한 외부 실행 결과는 대조 전 재실행하지 않는다.
- YAML 품질 차단 목록의 출처 없는 확정 주장 누락을 보완한다.
- EXPERIMENT는 변형별 별도 원자 업무로 명확히 하여 책임 인간 한 명 원칙을 유지한다.
- 모델 프로필·정책 버전·로드 커밋을 산출물 계약에 포함한다.

## 6. 확인 범위

문서·YAML 파싱, 필수 필드·예시·규칙 ID의 연결, 승인 매니페스트 범위, 인용한 이슈 결정과의 일치, 내부 파일 링크, 기존 인간·슬롯 보존을 확인한다. 저장소에 없는 실행기를 실행하거나 실제 게시·루틴을 시험했다고 보고하지 않는다. 최종 검증 결과와 반영 커밋은 원본 이슈 댓글에서 확인한다.
